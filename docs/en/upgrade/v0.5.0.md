# Fboard 0.5.0 Upgrade Notice

This page collects the user-visible changes introduced in 0.5.0 that need attention when upgrading. Back up your database before upgrading.

## Pinyin search (`pinyin_index`)

Nine tables gained a nullable `pinyin_index` text column and admin list endpoints now support pinyin fuzzy search (full pinyin + initials). For example, searching `fwq` in node management matches the node named `服务器`.

**Affected tables:** `v2_notice`, `v2_knowledge`, `v2_coupon`, `v2_payment`, `v2_server`, `v2_server_machine`, `v2_cert_templates`, `v2_gift_card_template`, `v2_ticket`, `v2_plan`.

### Required: backfill existing rows

The migration only adds the column — it does **not** populate it. Run the backfill command once after upgrading, otherwise pinyin search returns nothing for pre-existing data:

```bash
php artisan fboard:sync-pinyin
```

The command iterates all pinyin-searchable tables in chunks (200 rows) and regenerates `pinyin_index` for every row. It uses a direct query-builder update so the model `saving` event is **not** re-triggered (avoids side effects such as the `Server` model's group-id permission checks on historical data).

New rows created through the admin panel are indexed automatically by the `HasPinyinSearch` trait (no action needed).

### For developers

Models that should support pinyin search can opt in with the `HasPinyinSearch` trait:

```php
use App\Traits\HasPinyinSearch;

class MyModel extends Model
{
    use HasPinyinSearch;

    protected array $pinyinSearchable = ['name', 'description'];
}
```

The model must have a nullable `pinyin_index` text column. The trait maintains it on `saving` and provides `scopePinyinSearch($query, $search, $fields)` for controller queries.

## Multiplex configuration migration

Multiplex (多路复用) configuration is now **a single shared object** under `protocol_settings.multiplex`, managed centrally by the **高级设置** (Advanced settings) dialog in the node edit form. Inline multiplex fields were removed / unified across protocols.

What changed:

- **Shadowsocks / ShadowQUIC / Sudoku** now take the shared object form (`enabled`, `protocol`, `max_connections`, `padding`, `brutal`).
- **Mieru** no longer has an inline multiplex field at all — configure it via the Advanced settings dialog.
- **Sudoku** normalizes the object to mihomo's string switch (`on` / `off`) for the node config; a legacy scalar value (`off` / `auto` / `on`) is still passed through.
- The Sudoku network preset no longer inlines `multiplex`.

> ⚠️ If you had a plain-string `multiplex` value stored in an older server config (e.g. `"off"`), it is no longer interpreted the same way. Open each affected node's **高级设置 → 多路复用** tab and re-apply the intended multiplex settings. The legacy scalar is preserved for Sudoku, but for other protocols re-open and confirm the dialog to write a complete multiplex object.

The node config builders now emit `multiplex` for Shadowsocks / Mieru / ShadowQUIC / Sudoku, so the setting survives node-side config generation and client subscriptions.

## Shadowrocket subscription REMARKS header

The Shadowrocket subscription response now includes a `REMARKS=<app_name>` header, taken from the `app_name` admin setting (default `Fboard`). This makes the application name show up in the client. No configuration is required; change `app_name` in settings if you want a different label.

## Other changes

- Node **batch replace** behavior changed: `POST /server/manage/batchReplace` is now a full-table field replacement and the `ids` parameter is gone. See [Server batch operations](../management/server-batch-operations.md).
- **Certificate templates** were added — reusable cert/key presets applied from the advanced protocol configuration. See [Certificate templates](../management/cert-templates.md).
- Machine-level node **binding / unbinding** was added. See [Machine-level node binding](../management/machine-node-binding.md).
- Docker multi-arch builds were reworked (arm64 now built natively on ARM runners). No user-facing action.
