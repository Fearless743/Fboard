# 节点批量操作

**批量替换** API 支持跨所有节点一次性替换某个字段的子串。它取代了旧的「勾选行 + 单字段替换」行为，改为**全库字段替换**。

> ⚠️ 该操作会作用于表中**每一个**节点——没有行选择，也没有分组/机器过滤。请先在非生产环境用数据演练后再执行。

## API

### `POST /{secure_path}/server/manage/batchReplace`

请求体参数（JSON）：

| 参数 | 必填 | 说明 |
|------|------|------|
| `field` | 是 | 要操作的字段，必须是下方白名单之一 |
| `search` | 是 | 要查找的子串 |
| `replace` | 是 | 替换文本，可为空字符串（相当于删除式替换） |

响应：

```json
{ "status": 200, "data": { "changed": 12 } }
```

`changed` 表示实际被修改的节点数（替换后无变化的行会被跳过）。

## 支持的字段

控制器强制白名单校验，不在列表内的字段返回 `400 该字段不支持批量替换`。

**标量字段** — 对字段值做纯文本子串替换：

- `name`
- `host`
- `port`
- `code`

**JSON 字段** — 对列的**序列化 JSON 文本**做子串替换，可覆盖数组元素与嵌套值：

- `group_ids`
- `route_ids`
- `tags`
- `protocol_settings`
- `custom_outbounds`
- `custom_routes`
- `cert_config`
- `rate_time_ranges`

## JSON 字段如何被替换

JSON 字段会直接从数据库读取原始 JSON 字符串，对其执行 `str_replace($search, $replace, $rawJson)`。键名、值、数组元素都会作为字面子串被匹配。替换后的文本再解码回数组保存。

行为细节与风险：

- **子串语义，而非结构匹配。** 例如替换 `"1"` 也会命中 `"11"`、`"21"` 乃至 JSON 键名，而不仅是数组值 `1`。请尽量让搜索串足够精确。
- **非法 JSON 会中断。** 如果替换破坏了 JSON（例如引号不平衡），保存失败并返回 `400`；整个事务回滚，不会出现部分生效。
- **`protocol_settings` 保存时会再次归一。** `Server` 模型在赋值时会按协议定义对 `protocol_settings` 重新归一（含 REALITY 设置归一）。通过原始文本替换阶段的值，在保存时仍可能被该归一逻辑转换。
- **无变化的行被跳过。** 替换后无变化的行不计入 `changed`。

## 钩子

操作前后会触发两个钩子，插件可据此响应：

- `admin.server.batch_replace.before`
- `admin.server.batch_replace.after`

## 管理后台 UI

在**节点管理**中，批量替换对话框暴露同样的 12 个白名单字段（带友好标签）。选择字段、输入查找串与替换串后确认，界面会以成功提示展示被修改的节点数。

## 升级注意

0.5.0 之前的行为是勾选若干行、仅对这几行替换单个值字段。`ids` 参数已不存在。如果你的流程依赖按行替换，请改为匹配唯一子串（例如独特的主机名前缀）。
