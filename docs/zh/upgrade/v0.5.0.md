# Fboard 0.5.0 升级说明

本文档汇总 0.5.0 引入、需要升级时注意的用户可见变更。升级前请先备份数据库。

## 拼音搜索（`pinyin_index`）

9 张表新增可空的 `pinyin_index` 文本列，管理端列表接口支持拼音模糊搜索（全拼 + 首字母缩写）。例如在节点管理中搜索 `fwq` 可以匹配名为「服务器」的节点。

**涉及表：** `v2_notice`、`v2_knowledge`、`v2_coupon`、`v2_payment`、`v2_server`、`v2_server_machine`、`v2_cert_templates`、`v2_gift_card_template`、`v2_ticket`、`v2_plan`。

### 必做：回填存量数据

迁移只会加列，**不会**填充索引。升级后必须执行一次回填命令，否则存量数据的拼音搜索不生效：

```bash
php artisan fboard:sync-pinyin
```

该命令会分块（每块 200 行）遍历所有支持拼音搜索的表，为每一行重新生成 `pinyin_index`。它使用查询构造器直接更新，**不会**再次触发模型的 `saving` 事件（避免历史脏数据触发 `Server` 模型的分组权限校验等副作用）。

管理后台新建的数据由 `HasPinyinSearch` trait 自动维护索引，无需额外操作。

### 面向开发者

需要支持拼音搜索的模型可以接入 `HasPinyinSearch` trait：

```php
use App\Traits\HasPinyinSearch;

class MyModel extends Model
{
    use HasPinyinSearch;

    protected array $pinyinSearchable = ['name', 'description'];
}
```

模型需要有可空的 `pinyin_index` 文本列。trait 在 `saving` 时维护索引，并提供 `scopePinyinSearch($query, $search, $fields)` 供控制器查询使用。

## 多路复用配置迁移

多路复用（multiplex）配置统一为 `protocol_settings.multiplex` 下的**单一共享对象**，由节点编辑表单中的**高级设置**对话框集中管理。各协议的内联 multiplex 字段已移除 / 统一。

变更内容：

- **Shadowsocks / ShadowQUIC / Sudoku** 改为共享对象形式（`enabled`、`protocol`、`max_connections`、`padding`、`brutal`）。
- **Mieru** 不再有内联 multiplex 字段——请通过高级设置对话框配置。
- **Sudoku** 在节点配置侧将对象归一为 mihomo 字符串开关（`on` / `off`）；旧标量值（`off` / `auto` / `on`）仍会透传。
- Sudoku 网络模板不再内联 `multiplex`。

> ⚠️ 如果旧节点配置中存的是纯字符串 `multiplex`（例如 `"off"`），其解释方式已经改变。请逐个打开受影响节点的**高级设置 → 多路复用**标签页，重新应用预期的多路复用设置。Sudoku 会保留旧标量，但其它协议请重新打开并确认对话框，以写入完整的多路复用对象。

节点配置构建器现在会为 Shadowsocks / Mieru / ShadowQUIC / Sudoku 输出 `multiplex`，确保该设置在节点侧配置生成与客户端订阅中生效。

## Shadowrocket 订阅 REMARKS 头

Shadowrocket 订阅响应新增 `REMARKS=<app_name>` 头，取值来自 `app_name` 管理设置（默认 `Fboard`）。这会让应用名显示在客户端中。无需额外配置；如需不同文案，修改设置中的 `app_name` 即可。

## 其它变更

- 节点**批量替换**行为变更：`POST /server/manage/batchReplace` 改为全库字段替换，`ids` 参数已移除。见[节点批量操作](../management/server-batch-operations.md)。
- 新增**证书模板**——可复用的证书/私钥预设，从高级协议配置中一键应用。见[证书模板](../management/cert-templates.md)。
- 新增机器级节点**绑定 / 解绑**。见[机器级节点绑定](../management/machine-node-binding.md)。
- Docker 多架构构建重构（arm64 改为 ARM runner 原生构建）。无需用户操作。
